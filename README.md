# phish-bench

Code, data versions and raw results for the paper
**"Traditional Machine Learning versus Deep Learning for Phishing Detection in Remote Work
Environments: A Reproducible Comparison of Accuracy, Class Imbalance and Latency"**
(A. Tussupov, Astana IT University).

Every number in the paper's tables is generated by `src/make_tables.py` from the files in
`results/`; nothing is typed by hand.

## Quick start

```bash
pip install -r requirements.txt
bash scripts/fetch_data.sh     # downloads both datasets from pinned commits, checks SHA-256
bash scripts/run_all.sh        # runs experiments 1-5 and rebuilds the tables (~1.5 h on 2 CPU cores)
```

## Datasets

| ID | Dataset | Source (pinned) | Rows used |
|----|---------|-----------------|-----------|
| D1 | UCI Phishing Websites (Mohammad & McCluskey, doi:10.24432/C51W2X) | `fafal-abnir/phishing_detection@57c2cef` (`dataset.csv`, copy used by Shahrivari et al.) | 11,055 (A) / 5,849 unique (B) |
| D2 | Ebbu2017 URLs (Sahingoz et al., ESWA 2019) | `ebubekirbbr/pdd@90b394d` (`input/*.json`) | 54,634 unique URLs after removing the scheme and duplicates |

D1: 5,206 of 11,055 rows (47.1%) are exact duplicates. D2: the scheme (`http://`, `https://`)
is stripped because 36.8% of legitimate but 1.8% of phishing URLs use `https://` in the raw
corpus, an artefact of collection.

## Experiments

| Script | What it does | Main output |
|--------|--------------|-------------|
| `src/exp1_uci_ml.py` | 7 ML models, stratified 10-fold CV on D1, protocol A (all rows) and B (deduplicated) | `results/exp1_uci_ml_summary.csv` |
| `src/exp2b_uci_cnn.py` | 1D-CNN after Yerima & Alzaylaee (2020) on the same folds | `results/exp2b_uci_cnn_summary.csv` |
| `src/exp2_urls.py [seed]` | 7 ML (20 lexical features) + 3 char-level DL models on D2, 80/20 split, seeds 42-44 | `results/exp2_urls_summary.csv`, `results/scores/*.npz`, `results/models/` |
| `src/exp3_imbalance.py` | the trained D2 models at 10 %, 2 %, 1 % phishing prevalence + analytic precision | `results/exp3_imbalance.csv` |
| `src/exp4_latency.py` | single-URL latency (1 thread), batched latency, model size, peak RSS | `results/exp4_latency.csv` |
| `src/exp5_cascade.py` | XGBoost -> CNN cascade for uncertain URLs | `results/exp5_cascade.csv` |
| `src/make_tables.py` | builds `paper/tables/*.tex` and `results/tables.md` | |
| `src/make_figure.py` | precision-vs-prevalence figure | `results/fig_precision_prevalence.pdf` |

Shared preprocessing, features and metric definitions are in `src/common.py`; model
definitions in `src/models_ml.py` and `src/models_dl.py`. The positive class is always phishing.

## Environment used for the reported results

Intel Xeon @ 2.80 GHz (2 logical CPUs), 7.8 GB RAM, no GPU, Linux 6.18, Python 3.13.16,
NumPy 2.5.3, pandas 3.0.5, scikit-learn 1.9.1, XGBoost 3.4.1, PyTorch 2.14.1 (CPU execution).
Also recorded in `results/exp2_dataset_info.json`.

Seed 42 of experiment 2 shared the CPU with experiment 2b, so its wall-clock training times are
excluded from the training-time column (seeds 43-44 only). Latency was measured after all
training had finished, on an otherwise idle machine.

## Repository layout

```
data/        datasets (re-created by scripts/fetch_data.sh)
src/         experiment code
results/     per-fold/per-seed CSVs, test-set scores (.npz), fitted models, logs
paper/       paper.tex, generated tables, figure
scripts/     fetch_data.sh, run_all.sh
```

`results/models/Random_Forest.joblib` is 192 MB; it is regenerated by `exp2_urls.py` and can
be left out of version control (see `.gitignore`).
